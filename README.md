# outage-odesa: сборщик

Раз в 5 минут (GitHub Actions) открывает страницу ДТЭК Одесские электросети настоящим браузером (Playwright),
достаёт график (`DisconSchedule.fact` и `DisconSchedule.preset`) и отправляет его в Cloudflare Worker бота
на закрытый адрес `/ingest`. Если данные получить не удалось, отправляет отчёт об ошибке: Worker сам
считает сбои и пишет администратору в Telegram.

## Секреты репозитория

Settings → Secrets and variables → Actions → New repository secret:

| Имя | Значение |
|---|---|
| `WORKER_URL` | адрес Worker, например `https://outage-odesa.<аккаунт>.workers.dev` (без `/ingest` и без слэша в конце) |
| `INGEST_TOKEN` | та же случайная строка, что в секрете `INGEST_TOKEN` у Worker |

Репозиторий публичный, поэтому логи запусков тоже публичные. Скрипт не печатает ни адрес Worker, ни токен,
а GitHub дополнительно маскирует значения секретов. Не добавляй в этот репозиторий workflow с триггерами
`pull_request_target` или `workflow_run`: они могут отдать секреты чужому коду.

## Что делает каждый запуск

1. Открывает страницу в Chromium (до 3 попыток), читает `window.DisconSchedule`; если его нет в `window`,
   вырезает JSON из HTML. Ничего из страницы в Node не исполняется: только `JSON.parse`.
2. Проверяет форму данных (есть `fact.data`, `preset.sch_names`, ключи суток выглядят как unix-время).
3. Отправляет `{fact, preset, contentHash}` в Worker, до 3 попыток при сетевых ошибках и ответах 5xx.
4. Код выхода 0, если Worker принял данные или отчёт об ошибке. Код 1 (красный запуск) только если Worker недоступен,
   отверг токен (403) или не заданы секреты: это ошибка настройки, и её надо видеть.

Сбой ДТЭК красным запуском не помечается намеренно: иначе GitHub присылал бы письмо на каждый неудачный запуск.
О таком сбое ты узнаёшь из Telegram.

## Расписание: что надо знать

- GitHub не гарантирует, что `*/5` сработает ровно каждые 5 минут: бывают задержки на десятки минут, иногда пропуски.
  Если это случится, бот честно покажет «данные устарели», а админ получит алерт «данные не обновлялись N мин».
- В публичных репозиториях GitHub отключает расписание после 60 дней без активности в репозитории. Сами запуски
  не считаются активностью. Если алерт «данные не обновлялись» пришёл надолго раньше или позже, проверь вкладку Actions:
  там будет кнопка включения. Чтобы не ждать, раз в месяц коммитни любое мелкое изменение.
- Запуск вручную: Actions → Collect → Run workflow.

## Файлы

- `scripts/collect.mjs`: сборщик.
- `scripts/lib/extract.mjs`: разбор и проверка данных.
- `scripts/probe.mjs` + `.github/workflows/probe.yml`: одноразовая проверка «пускает ли ДТЭК» (запуск вручную).
- `tests/`: `npm test` (быстрые, без сети) и `npm run test:e2e` (с настоящим Chromium, локальные заглушки).
